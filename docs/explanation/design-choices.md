# Design Choices

Why LGOS works the way it does. Add a row for each significant decision; when
one changes, update its row.

| Choice | Why | Cost | Revisit when |
| --- | --- | --- | --- |
| Background runs live only in Hatchet; LGOS keeps no Response table. | One source of truth: no outbox, resubmission, cleanup, or migrations. | Polling depends on Hatchet; retention is Hatchet's (30 days by default when self-hosted), not `store`; an unknown ID takes about 17 seconds to return 404. | Responses must outlive Hatchet or its retention. |
| The background worker runs the foreground Responses path, with no retries or checkpoint resume. | One execution path; resuming needed a second runner and recovery machinery. | A run that raises fails. A run reassigned after its worker dies starts over, and an interrupt answer that had already applied then fails as stale. | Runs are too long or expensive to repeat. |
| Background creates accept an `Idempotency-Key` header. | SDKs and gateways retry creates, which would otherwise start duplicate runs. | It is not an OpenAI header, and gateways must forward it. | OpenAI offers a retry-safe create. |
| A node calls `interrupt()` at most once per invocation. | LangGraph's interrupt IDs then identify each pause without scanning checkpoints. | A node cannot ask two questions. | LangGraph gives each `interrupt()` call a unique ID. |
| Paused interrupt runs expire through `delete_expired_interrupt_runs`, which the host schedules. | The open-source Postgres checkpointer has no TTL; this mirrors LangGraph Agent Server's checkpointer TTL through the checkpointer API alone, so it works with any saver and needs no optional dependency such as Hatchet. | Each sweep reads every checkpoint in the saver, and an answer arriving after expiry fails with 409. | LangGraph checkpointers expire threads natively. |
| LGOS reports each graph execution through the OpenTelemetry API as a GenAI `invoke_workflow` span and `gen_ai.invoke_workflow.duration` histogram. | Agent frameworks such as Google ADK, Microsoft Agent Framework, and Pydantic AI instrument their own runs through the API, and the GenAI conventions name LangGraph graphs as workflows. | A core dependency on `opentelemetry-api`. The GenAI conventions are still in development and may rename these signals. Langfuse exports GenAI spans by default, so LGOS configures its client to skip this span and keep the callback's root observation; an application-created Langfuse client needs the same filter. | LangGraph ships its own OpenTelemetry instrumentation, or the GenAI conventions stabilize. |
| A graph run that ends before its output exists fails, cancellations included: the workflow span is `ERROR` and both signals carry the cancellation's `error.type`. | The conventions define no cancelled outcome, and widely used tracers record cancellation as a failure: OpenTelemetry's [GenAI utilities](https://github.com/open-telemetry/opentelemetry-python-genai/pull/520), [Logfire](https://github.com/pydantic/logfire/blob/211dfb3618187f57d68cbe82cbd6c31f8bb92475/logfire-sdk/logfire/_internal/tracer.py#L238-L241), [LangSmith](https://github.com/langchain-ai/langsmith-sdk/blob/ff34d38d91cbd4041972e813ab1bd864ebe5b17f/python/langsmith/run_helpers.py#L725-L733), [ASP.NET Core](https://github.com/dotnet/aspnetcore/blob/96b1f9ffb024e0e648383c2c014de461d2591daa/src/Hosting/Hosting/src/Internal/HostingMetrics.cs#L84-L90), [.NET's HttpClient](https://github.com/dotnet/runtime/blob/f98a059f8d6b543341f4645e2b32174560f579f5/src/libraries/System.Net.Http/src/System/Net/Http/DiagnosticsHelper.cs#L89-L90), and [Go's HTTP client](https://github.com/open-telemetry/opentelemetry-go-contrib/blob/318f5f91d789469a87f062b28e41c6ebbdffb220/instrumentation/net/http/otelhttp/transport.go#L300-L302). A stream closed mid-run fails too, so a client disconnect fails whether it arrives while the graph works or while it waits on the client. | Cancellations count as failures in error rates and alerts; the `error.type` value, such as `asyncio.exceptions.CancelledError` or `GeneratorExit`, tells them apart. This departs from the [HTTP conventions](https://opentelemetry.io/docs/specs/semconv/http/http-spans/), which leave a cancellation the caller intended unset; from the official LangGraph server ([`langgraph-api`](https://pypi.org/project/langgraph-api/) 0.15.1 `worker.py`), which counts a requested cancellation apart from failures; and from OpenTelemetry Python's [`use_span`](https://github.com/open-telemetry/opentelemetry-python/blob/5e8083e845dc0b0225d8674240c556c879ce852f/opentelemetry-api/src/opentelemetry/trace/__init__.py#L606-L609), which leaves cancellations unset. | The conventions add a cancelled outcome ([semantic-conventions#560](https://github.com/open-telemetry/semantic-conventions/issues/560)). |
| `lgos serve` and `lgos worker` host a registry factory: the `server` extra owns logging, CORS, telemetry setup, persistence, interrupt expiry, and the Hatchet worker, while the library API leaves them to the host. | The demo, the coding agent, and every starter project copied the same hosting code; one opt-in runtime removes the copies and leaves projects only their graphs. Like [Aegra](https://docs.aegra.dev/guides/deployment), it ships as a dependency inside the project's own image, so the project's lockfile describes what runs. The factory receives the checkpointer, store, and run coordinator, so registration validates them exactly as in library mode. | A heavy extra with every integration, opinionated defaults that a project escapes only through the library API, and no hook for custom routes, middleware, or authentication. Each API process runs its own expiry sweep unless its interval is `0`. | Projects need custom routes or authentication inside the server, or reading LangGraph's `langgraph.json` becomes worth a second registration format. |
